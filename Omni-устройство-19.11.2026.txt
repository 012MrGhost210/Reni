2. АРХИТЕКТУРА
--------------------------------------------------------------------
Супервизор omni + доменные агенты. Каждый агент = папка (локация)
+ свои сессии OpenCode + свои правила/скиллы/сабагенты.

    Илья (пользователь)
        |  (чат)
    [ omni ] — супервизор: C:\...\OpenCodeProject\Omni
        |  (запуск сессий через OpenCode HTTP API; отчёты; каталоги)
        +--> [ rates ]   (Rates\)      ставки банков: Exchange -> weekly_rates.xlsx
        +--> [ meeting ] (ExpressMit\) встречи: eXpress-конференция + календарь Exchange
        +--> [ NPF ]     (NPF\)        репо НПФ: CSV брокера -> реестры ПР/СС -> СЧА в чат
        +--> [ learning ](Learning\)   обучение: база знаний + создание/публикация скиллов
        +--> [ medic ]   (Medic\)      «полевой санитар»: реанимация мёртвых/деградировавших сессий

Сабагенты (работают ВНУТРИ сессии своего прайма, только отчитываются):
- omni: agents-keeper (каталог агентов), rules-keeper (каталог правил).
- rates: mail-hunter, excel-filler.
- NPF: repo-broker, ev-sums.
- meeting, learning, medic: без сабагентов.

ЖЁСТКОЕ ПРАВИЛО делегирования (введено после инцидента 18.11):
задачу домена агента omni НЕ выполняет в своей сессии, даже если
запрос пришёл напрямую и инструменты (MCP/CDP) у него есть.
Операции с высокой рисковой нагрузкой (отправка в чаты/почту,
CDP eXpress) — ТОЛЬКО в прайм-сессии доменного агента.

Идентификация:
- Маркер агента = файл AGENT.md в корне локации (имя, роль,
  сабагенты, MCP, data-зона, статус).
- AGENTS-REGISTRY.md (в Omni\) — ЕДИНСТВЕННЫЙ источник правды

- AGENTS-CATALOG.md — «кто что умеет и как» (ведёт agents-keeper).
- RULES-CATALOG.md — каталог всех правил, глобальных и локальных

Саморепорт: агент сообщает omni о себе при создании и при любом
изменении (новые возможности, скиллы, MCP, сбои) — файл в
Omni\agents-inbox\ (шаблон README.md), обрабатывает agents-keeper,
карточка обновляется в AGENTS-CATALOG.md, отчёт уходит в
agents-inbox\processed\.

3. ПАМЯТЬ: СЛОИ И ФАЙЛЫ
--------------------------------------------------------------------
Контекст — единственный ограниченный ресурс (100k токенов).
Вся остальная память — в файлах. 4 слоя:

| Слой | Где | Когда читается |
|---|---|---|
| 0 рабочая | контекст сессии | текущая задача + свежие решения |
| 1 состояние | Omni\STATE.md («сейв-файл») | старт сессии, после сжатия, при ротации — единственный ОБЯЗАТЕЛЬНЫЙ к чтению |
| 2 истина | AGENTS-REGISTRY.md, AGENTS-CATALOG.md, RULES-CATALOG.md, playbook.md, AGENT.md | фрагментами: сначала grep, потом read offset/limit |
| 3 холод | agents-inbox\processed\, отчёты сабагентов, архивы STATE | только при конкретном вопросе |

STATE.md = append-only журнал (Дата | Шаг | Результат | Далее)
+ раздел «Текущая задача» (<= 10 строк, всегда актуален).
Правила: после каждого значимого шага — строка в STATE; историю не
переписывать; лимит журнала 40 строк (перелим — сводка по дате в
STATE-archive.md); операционные детали (SHA256, ID) — в файлы,
в журнал только путь.

У каждого доменного агента свой STATE.md в локации (у NPF, medic —
есть) + свои рабочие файлы.

Каталог канонических файлов:
- Omni\playbook.md — плейбук прайма: золотые правила, слои памяти,
  дисциплины (чтения, сабагентов, вывода), протокол ротации (§5),
  поведение при сжатии (§6), что прайм НЕ делает (§7), рецепты
  OpenCode API (§8).
- work\README.md — правила общей data-зоны.
- Глобальные правила системы: C:\Users\Ilya.Matveev2\.config\opencode\AGENTS.md
  (саморегуляция Omni: правило помечки агента, саморепорт, как
  находить агентов).
- Каждый агент: AGENT.md + AGENTS.md/README + свои скиллы
  (.opencode\skills\...) + свой STATE.md.

4. ЖИЗНЕННЫЙ ЦИКЛ ЗАДАЧИ (на реальном примере: «обнови репо НПФ»,
   19.11.2026)
--------------------------------------------------------------------
1. Илья -> omni: «обнови репо НПФ, привлеки агента».
2. omni проверяет: нет ли AGENT.md в своей папке? Да — я omni.
   Задача доменная (НПФ) -> делегирование. Сессия NPF не
   запускается сабагентом, а ОТДЕЛЬНОЙ сессией через OpenCode API:
   POST /api/session {"title": "NPF: обновление репо 19.11.2026",
   "location": {"directory": "...\NPF"}} -> POST /prompt с текстом
   задачи. (Хелпер: Omni\scripts\omni_session.py, end-to-end.)
3. NPF-сессия: читает свой AGENT.md/STATE.md, находит письмо
   брокера в Exchange (MCP exchange), скачивает 2 CSV, валидирует,
   пре-чек (жив ли Excel, открыты ли реестры, lock-файлы).
4. Аномалия A1: work-копии реестров расходятся с сетевыми (чей-то
   Excel на сети переписал файл) -> стоп, диагностика raw-XML,
   вердикт «float-сериализация, данных 0» -> синк work->net,
   forensic-снапшот. Повторилось 2 раза (ПР, потом СС) -> 3
   прогона пайплайна, 3-й — BROKER_RUN_OK (45,5 с):
   XML-хирургия xlsx (только лист «Реестр» + sharedStrings),
   zip-diff чистый, Excel COM 0 ошибок, SHA256 сверка с сетью.
5. СЧА-сообщение в eXpress-чат «КазнAInfo» (MCP express) +
   верификация доставки (read чата, sync_id).
6. Отчёт NPF в сессию (<= 30 строк). omni получает (watcher-скрипт
   в фоне ждал стабильного idle), верифицирует САМ по факту
   (SHA256 work-реестров = лог прогона), доносит Илье, пишет
   строку в STATE.md.
7. Если агент изменился (новые возможности/сбои) — саморепорт в
   agents-inbox\ -> agents-keeper -> AGENTS-CATALOG.md.

Раскладка: ~49 мин — ожидание ответа Ильи на вопрос агента

5. ДИСЦИПЛИНЫ И ПРОТОКОЛЫ
--------------------------------------------------------------------
Контекст (анти-сжатие, playbook.md §5):
- Ротировать ДО сжатия и по закрытым циклам: новая сессия
  «omni: <задача>, продолжение N <дата>» через API, старт —
  только AGENT.md + STATE.md. Старая сессия — история (не удалять).
- Порог: ротация при ~50–60% окна (100k) или после закрытого цикла.
- Не тащить в контекст: сырой JSON (через execute/Code Mode —
  fetch -> проекция -> дайджест 3–10 строк), целые большие файлы
  (grep -> read фрагмента), содержимое отчётов (путь + хэш).
- Файл > 150 строк: сначала grep/glob, потом read с offset/limit.
- Файл, уже прочитанный, не перечитывать.
- Отчёт сабагента прайму: <= 30 строк, без сырого содержимого
  файлов (только находки, пути, хэши).
- Верификация дёшево: Test-Path, Get-FileHash, grep -c — а не
  чтение файла целиком.

Сабагенты (жёстко): вся неоднозначность разбирается праймом ДО
запуска (сабагент не спрашивает — отчитывается). Доменные агенты —
НЕ сабагенты omni.

Вывод Илье: что сделано (пути, хэши), что ждёт (решения с
вариантами), что найдено. Без пересказа процесса. Длинные
результаты — в файл, в чат — выжимка + путь.

Медицина: medic — отдельный агент, командой «medic: <агент>,
<что случилось>» (или обнаруженной мёртвой сессией) — запускается
сессия medic; он диагностирует через API и реанимирует
(реанимационный промпт в ту же сессию или «продолжение N»).
Отработка сценариев 1–3 проверена на песочнице 17.11; сценарий 4
(«мёртвая сессия -> продолжение N») — отложен до реального
инцидента.

6. ИНСТРУМЕНТЫ
--------------------------------------------------------------------
- OpenCode HTTP API (порт ДИНАМИЧЕСКИЙ — резолвинг: PID процесса
  opencode-cli -> LISTENING-порт в netstat; креды Basic auth из
  ~\.config\opencode\service.json). Сессии: создать, prompt,
  читать сообщения/контекст, ждать idle, удалять. ВАЖНЫЙ КВИРК,
  найден 19.11: инструмент `question` (агент задал вопрос
  пользователю) = Form в API: GET /api/session/{id}/form,
  ответить — POST /api/session/{id}/form/{formID}/reply
  ({"answer": {key: value}}) — можно отвечать на вопросы агентов
  БЕЗ UI. POST /prompt к занятой сессии = 200, но текст идёт в
  очередь (inbox) и доставляется после текущего run.
- MCP-серверы (глобально): exchange (почта + календарь), express
  (корпоративный мессенджер eXpress: чаты, отправка), jira,
  confluence. Отдельные агенты отключают себе MCP локальными
  opencode.jsonc (у medic все 4 отключены; у NPF jira/confluence).
- CDP (Chrome DevTools Protocol, 127.0.0.1:9222) — для UI
  eXpress (создание конференций: meeting). Самый хрупкий
  инструмент (зависит от версий UI; квірки селекторов
  задокументированы в SKILL.md meeting).
- Скиллы: глобальные (~\.config\opencode\skills: answers-charts,
  browser, documents, express-meeting, mail-to-treasury-chat,
  mail-with-signature, opencode, pdf, presentations, report,
  rusfar-daily, skill-creator, spreadsheets, visualize) +
  локальные в локациях агентов (у NPF: broker-reports-npf c
  broker-run.py и SKILL.md; у meeting: express-meeting-локалка).
  Есть конфликт/дубль express-meeting (глобальный vs локальный) —
  открытое решение #2.
- Python через shell — основной язык скриптов (API-хелперы,
  диагностика, пайплайны). cp866-консоль мусорит кириллицу —
  в каждом скрипте sys.stdout.reconfigure(encoding="utf-8").
- execute (Code Mode) — JS-рантайм внутри OpenCode: HTTP,
  обработка JSON без тащить сырьё в контекст. Таймаут ~60–120 c,
  sleep нет — длинные ожидания НЕ тут, а в Python-цикле.
- Сетевые UNC-пути — напрямую (чтение + синк work->net).
